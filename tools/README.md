# Building and checking Humanity, Live

- `tools/tpl.html` is the source. `python3 tools/build.py` (run from `tools/`) writes `index.html` (CDN three.js) and `test.html` (local three.js for tests).
  It needs `mask.b64` and `topo.b64` next to it.
- Copy `tools/index.html` to `public/index.html` to ship.
- Stability check: `npm i three@0.128.0` inside `tools/`, `pip install playwright`, then `python3 tools/smoke.py`. It must print only PASS lines before anything is pushed.
- `public/changelog.json` feeds the "What's new" list in the app (newest first).

## Handoff board (read this first, every job)
- tools/HANDOFF.md lists problems one job found for another to fix, grouped by owner (content, species, cards, graphics, map, art, behavior, ecosystem, realism).
- At the start of every run: read it and fix the items for your area (spend at most about 10 minutes on them). Then ALWAYS do your own job's full normal run as well: handoff fixes are extra work, never a replacement for your main work. At the end: add anything you found but didn't fix, under the job that should fix it, and delete lines you fixed.
- Job logs: AUDIT.md (realism), BEHAVIOR.md, ECOLOG.md (interactions), MAPLOG.md, ARTLOG.md, SPECIESLOG.md, HEALTH.md, ROADMAP.md (weekly priorities). Skim the ones related to your area.

## Trading cards
- `public/cards.json` is generated by `tools/cards.js` (build.py runs it) from the page's own data (SP, BIG, DISC) and the public/*.json data files. Don't edit it by hand; new species, events, wonders, journeys, extinctions, storms and landforms become cards automatically.
- Seasons follow the world clock (see SEASONS in cards.js). A season's cards can only be earned while that era is playing; after that they can only be traded.
- Every found copy gets a random serial number from 1 to 71,250,000 (one per year the world covers), unique per card; trades move the numbered copy.
- The server side is in src/worker.js (`/api/cards/*`, tables ckey, cuser, card, offer, ipday). Event cards (`ev-*`) are only granted while the event is live. Trading needs Google sign-in (GOOGLE_CLIENT_ID var). Paid packs stay off until a STRIPE_SECRET exists.
- Card quests: an owned card is half a card until finished. Finding it (tapping the animal: `cardSpot`; opening its info card: `showEvent` via `cByName`; watching it live: `cardWitness`) unlocks its questions; answering them all calls `/api/cards/done` (table `cdone`). Plants and cards from eras that have ended go straight to the questions (`cState`).
- Questions are generated by cards.js into `public/quiz/<season>.json` from the same sourced data as the card: when it lived, diet, a real fossil site (wrong sites are 1,500+ km from every known site), its date, its own fact. Never hand-write a question or answer; fix the source data instead.

## Test tools (never shipped)
All of these need `python3 build.py` first (they load `tools/test.html`) and run headless Chrome with software WebGL. `harness.py` holds the shared bits (local server on a free port, open a year, close the intro, move the camera, read frame stats); new tools should import it instead of copying setup code.

- `python3 perf.py` prints JS ms per frame, render ms, fps, draw calls and triangles for 5 eras (Cretaceous Montana, Ice Age France, Classical Greece, Renaissance Italy, New York 1960), each from continent height and from the ground. About 2.5 minutes.
  - Before a change: `python3 perf.py --save /tmp/before.json`. After: `python3 perf.py --compare /tmp/before.json` shows % change per view and totals, marks anything more than 5% worse with `!`, and exits 2 if JS ms, triangles or draw calls got worse (JS changes under 1 ms are ignored as noise).
  - `--eras 1500 1960` runs only some years; `--ms 5000` samples longer for steadier numbers.
  - Software WebGL makes fps low and noisy; JS ms and triangles/draw calls are the numbers to trust. Compare only runs made on the same machine.
- `python3 shots.py <year,lat,lon,alt> ...` screenshots each view (alt 1.5 ground, 10 region, 60 continent) into `shots/now/` and makes `sheet.png`, a labelled grid of them. BCE years are fine (`-70000000,47,-107,1.5`). Add a fifth field to run page code first, e.g. `1960,40.7,-74,1.5,cam.yaw=1`.
  - `--file views.txt` (one view per line), `--out shots/before`, `--hide-ui` (only the 3D world), `--scale 2` for shots a person will look at.
  - Before/after for art changes: shoot the same views into `shots/before` and `shots/after`, then `python3 shots.py --pair shots/before shots/after` writes `shots/after/pair.png` side by side.
- `python3 validate.py` checks every public/*.json, cards.json and the rules in interactions.json (weights 0-1, every rule sourced). Errors (exit 1): missing titles, years outside the clock, coordinates out of range or at 0,0, exact duplicates, duplicate card ids, card years outside their season, bad rarity. Warnings: land things (cities, wonders, fossil sites, non-naval battles) more than 2 degrees from present-day land, same title twice in a year, cards without a fact or with an odd Wikipedia title, time ranges that run backwards, files with no source note. `--all` lists every warning. Run it before pushing any data change; when you add a new data file, add its layout to SCHEMA at the top.
- `python3 smoke.py 1815 -480` runs only the smoke cases for those years, for quick checks while working. The full `python3 smoke.py` (about 8 minutes) is still the gate before pushing.
- `python3 models.py` renders every instanced shape (dinosaurs, mammals, sea life, people, horses, vehicles, ships, trees) alone in daylight from the side (forward = left), front three-quarter and top, into `shots/models/sheet.png` (one PNG per shape too), and prints triangles, max instances and height/length measured in people (person = the `bodyM` figure; in-game scale per instance is on top of this). About 10 seconds.
  - `python3 models.py thero cera` only shapes whose name contains those words; `--list` only prints the numbers. Exits 1 if an animal is over 300 triangles or anything else over 600.
  - Try a new shape before editing tpl.html: `--js new.js` where new.js is page code that evaluates to `{name: geometry or [geometries]}` (THREE, mergeG, BASE and all page variables are in scope); it renders as `new.<name>` next to the live ones.
  - `--save m.json` / `--compare m.json` show triangle changes per shape.
  - Page variables live inside a block, so tools reach them through the test hook `HS.X(code)` (eval inside the page's scope), not as window globals.
- `python3 sizes.py` shows where the page's bytes go: each `// ====` section of tpl.html raw and gzipped, the biggest single lines (data tables), the embedded mask/topo, and the built index.html gzipped. `--save`/`--compare` show the change per section (gzipped KB is what visitors download).
- `ARTLOG.md` is the art and tools job's log (newest first).

## City founding years
- `public/cities.json` rows are `[name, lat, lon, population, country, foundedYear?, 1 if that year is the earliest written record?]`. Founding years come from Wikidata (inception P571 and earliest written record P1249, CC0), matched to each city by name within 0.3 degrees, earliest date kept.
- Old World dates from 1800 on in East/South Asia, Turkey, Iran and Europe are left out (they are usually municipal mergers or new city status, not foundings), as are Brazil's post-1900 municipal splits (except planned cities) and Mexico City's 1928 boroughs. A city without a year keeps the regional gate in `cityGate`.
- A city is hidden before its founding year; cities of 500k+ get a "founded" / "first written record" event (`FD`, `fireFounding`).

## Backups and admin
- Time machine (owner only): with the admin key saved (type `/admin <key>` in chat once), Settings shows Time machine. It opens `/#preview=<year>`, which the server confirms with `/api/admin/check`; that view runs on the device only: no shared-world connection, no saving, no cards or chat. Without a valid key the hash is dropped and the live world loads.
- Every night (11:00 UTC, about 3 AM Pacific) the worker saves the world, chat, ideas, alerts and all cards to the BACKUPS KV namespace (gzip, last 30 days). POST /api/admin/backups {key} lists them; POST /api/admin/backup {key} makes one now; POST /api/admin/restore {key, day, confirm:"RESTORE <day>", tables:[...]} restores (it saves the current state first). The key is the ADMIN_KEY secret; never put it in the repo.
- Never change table layouts in a way that breaks restoring older backups.

## Play as an animal
- Tapping a wild land animal offers "Play as this animal" (playAs). playSteer turns the joystick (relative to the camera) into the animal's next target before the normal AI moves it, so it walks with the same speeds, terrain and water rules, and other animals react to it by the same interaction rules. Attack and graze use the same odds as the AI. Hunger empties in about 5 minutes (faster when running).
- What an animal eats (eatsOf) comes only from interactions.json hunts and scavenges rules, with their sources shown as Evidence.

## Annoyance check
`python3 tools/annoy.py` (after build.py) counts automatic popups per minute at ground level in three eras and fails above 3 a minute. Run it before shipping anything that shows messages.

## Detailed animal models (.hlm)
A detailed model replaces an animal's simple shape up close. Format: "HLM1", header length, JSON header (vertex count, index count, bounding box, hip height, foot and tail positions, source), then int16 positions, int8 normals, uint16 UVs, uint16 indices and a JPEG texture. Models live in the worker's IMPORTS key-value store as file:<name> and are served at /a/<name>; to add one, upload the file to the Higgsfield file host and queue a job {"url": "...", "keep": "<name>.hlm"} (only that host is allowed, and only for kept files). Add the species key and file to MDL_LIST in tpl.html. If the file can't load, the old shape is used.
