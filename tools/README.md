# Building and checking Humanity, Live

- `tools/tpl.html` is the source. `python3 tools/build.py` (run from `tools/`) writes `index.html` (CDN three.js) and `test.html` (local three.js for tests).
  It needs `mask.b64` and `topo.b64` next to it.
- Copy `tools/index.html` to `public/index.html` to ship.
- Stability check: `npm i three@0.128.0` inside `tools/`, `pip install playwright`, then `python3 tools/smoke.py`. It must print only PASS lines before anything is pushed.
- `public/changelog.json` feeds the "What's new" list in the app (newest first).

## Trading cards
- `public/cards.json` is generated by `tools/cards.js` (build.py runs it) from the page's own data (SP, BIG, DISC) and the public/*.json data files. Don't edit it by hand; new species, events, wonders, journeys, extinctions, storms and landforms become cards automatically.
- Seasons follow the world clock (see SEASONS in cards.js). A season's cards can only be earned while that era is playing; after that they can only be traded.
- The server side is in src/worker.js (`/api/cards/*`, tables ckey, cuser, card, offer, ipday). Event cards (`ev-*`) are only granted while the event is live. Trading needs Google sign-in (GOOGLE_CLIENT_ID var). Paid packs stay off until a STRIPE_SECRET exists.

## Test tools (never shipped)
All of these need `python3 build.py` first (they load `tools/test.html`) and run headless Chrome with software WebGL. `harness.py` holds the shared bits (local server on a free port, open a year, close the intro, move the camera, read frame stats); new tools should import it instead of copying setup code.

- `python3 perf.py` prints JS ms per frame, render ms, fps, draw calls and triangles for 5 eras (Cretaceous Montana, Ice Age France, Classical Greece, Renaissance Italy, New York 1960), each from continent height and from the ground. About 2.5 minutes.
  - Before a change: `python3 perf.py --save /tmp/before.json`. After: `python3 perf.py --compare /tmp/before.json` shows % change per view and totals, marks anything more than 5% worse with `!`, and exits 2 if JS ms, triangles or draw calls got worse (JS changes under 1 ms are ignored as noise).
  - `--eras 1500 1960` runs only some years; `--ms 5000` samples longer for steadier numbers.
  - Software WebGL makes fps low and noisy; JS ms and triangles/draw calls are the numbers to trust. Compare only runs made on the same machine.
- `python3 shots.py <year,lat,lon,alt> ...` screenshots each view (alt 1.5 ground, 10 region, 60 continent) into `shots/now/` and makes `sheet.png`, a labelled grid of them. BCE years are fine (`-70000000,47,-107,1.5`). Add a fifth field to run page code first, e.g. `1960,40.7,-74,1.5,cam.yaw=1`.
  - `--file views.txt` (one view per line), `--out shots/before`, `--hide-ui` (only the 3D world), `--scale 2` for shots a person will look at.
  - Before/after for art changes: shoot the same views into `shots/before` and `shots/after`, then `python3 shots.py --pair shots/before shots/after` writes `shots/after/pair.png` side by side.
- `python3 validate.py` checks every public/*.json and cards.json. Errors (exit 1): missing titles, years outside the clock, coordinates out of range or at 0,0, exact duplicates, duplicate card ids, card years outside their season, bad rarity. Warnings: land things (cities, wonders, fossil sites, non-naval battles) more than 2 degrees from present-day land, same title twice in a year, cards without a fact or with an odd Wikipedia title, time ranges that run backwards, files with no source note. `--all` lists every warning. Run it before pushing any data change; when you add a new data file, add its layout to SCHEMA at the top.
- `python3 smoke.py 1815 -480` runs only the smoke cases for those years, for quick checks while working. The full `python3 smoke.py` (about 8 minutes) is still the gate before pushing.
- `ARTLOG.md` is the art and tools job's log (newest first).
